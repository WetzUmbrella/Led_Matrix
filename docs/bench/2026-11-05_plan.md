## 1. How we work tomorrow (and why not "everyone builds on their own PC")

The plan as first proposed was for everyone to build and test on their own PC and push to git now and then. It breaks in four places:

1. **Builds will not match.** Evidence is only valid if we know exactly which code produced it. Five people building from five local trees (different pulls, a local edit, a different `wifi_secrets.h`) gives five unknown builds. One build machine, one tag.
2. **The WiFi credentials are compiled into the firmware.** Every tile and Pico image needs the router's SSID and password at build time. If each person builds, each must have the right `wifi_secrets.h`, and one typo costs an hour of "why won't it join".
3. **Two Picos on one router break every tile's clock.** That is the 29 Oct bench finding. "Everyone tests their own hardware" means several Picos beaconing on the same router, which ruins every sync result in the room. Picos must be scheduled, not owned.
4. **Pushing to the same branch collides.** Five people pushing to `b4/phase2` and editing shared files (`bench_log.md`, the checklist) produce merge conflicts at the worst moment.

What we do instead:

- **One build machine (Ahsanul).** Tonight he builds every tile and Pico image from the tag, for each network, and shares them in one folder (section 3.2). Nobody else needs ESP-IDF.
- **Everyone flashes with esptool.** Flashing a prebuilt tile image needs only Python and `pip install esptool pyserial`. It works natively on Windows (COM ports, no WSL, no `usbipd`). A Pico is flashed by dragging a `.uf2` onto it.
- **Everyone logs on their own laptop** with `pc/tools/serial_log.py`, a timestamped serial logger in the repo (section 8). Each person runs the serial logs and PC tools for the tests they own.
- **Stations, not owners.** Three stations, each with its own network and at most one Pico (section 5).
- **Git: evidence only, own branch.** Each person commits only their own evidence files to `bench/<name>-5nov`, branched from the tag, and pushes at 12:30 and 17:30. Ahsanul merges them all into `b4/phase2` at the end. Nobody edits code, `bench_log.md` or the checklist on the day.
- **A code fix on the day goes through one gate.** Tell Ahsanul. He fixes it on `fix/<id>`, runs the host tests, re-tags `bench-5nov-2`, rebuilds and re-shares, and everyone reflashes. Every log after that says `bench-5nov-2`.

## 8. Test cards

Every card has the same fields. **Log** means start the serial or PC log before step 1 and keep it running until the card ends.

### How to flash and log (all cards)

- **Tile flash** (from the image folder):

  ```
  python -m esptool --chip esp32s3 -p COM<n> -b 460800 write_flash @flash_args
  ```

  Never use `erase_flash`: it wipes the board number stored in NVS.
- **Pico flash:** hold BOOTSEL, plug in, then drag the `.uf2` onto the RPI-RP2 drive.
- **Logging:** start the logger before step 1 of each card. It writes the header line below itself, timestamps every line, and appends, so 5 boots can go into one file. Ctrl+C stops it.

  ```
  python pc/tools/serial_log.py --port COM<n> --out <evidence path> --test <card> --who <name> --tile <board>/<MAC> --image <image> --net <A|B> --pico <A|B|none>
  ```

- **Log header** (written by the logger; type it yourself only with another terminal):

  ```
  # test=<card id> date=2026-11-05 tag=bench-5nov tile=<board no>/<MAC> image=<image name> net=<A|B> pico=<A|B|none> who=<name>
  ```

- **Times:** for any card marked *Times needed*, the logger must timestamp each line.

### B0: dry run on the sync rig (S1, P0, about 40 min)

- **Owner:** Ahsanul (Jia Jun wires B0.11).
- **Images:** `pico_plain_A`; `tile_plain_A` on tiles 1 and 2.
- **Steps:**
  1. Power Pico A **first**. Its log shows `COORDINATOR up: ip=...`, then `CL_STATS` and `LATE_HIST` lines.
  2. Power tiles 1 and 2. Each tile log shows `TN_RX_HOOK 1`, `TN_COMMS` state lines, `display_engine: test pin GPIO4, first tick ...`, `BCN,` lines (about 10 per second), and `TN_STATS ... dropped=0 ... foreign=0`.
  3. The Pico log shows `CL_EVENT ... JOIN node=<n>` for each tile, and `online=0x003` in `CL_STATS`.
  4. LEDs: the status pattern, not a moving pixel. The moving pixel needs an asset (Part F).
  5. B0.11 wiring: tile 1 GPIO4 to CH0/D0, tile 2 GPIO4 to CH1/D1, both tile grounds and the analyser ground joined.

     ```
     python pc/tools/skew_analyse.py dry_2tile.csv --ch-a "Channel 0" --ch-b "Channel 1" --marker --out dry_pairs.csv
     ```

     For sigrok, use `--ch-a D0 --ch-b D1`.
- **Pass:** `TICK IDENTITY CHECKED` printed; 1 ms pulses about 16.67 ms apart, and a 4 ms pulse every 64th.
- **Evidence:** notes only in `docs/bench/5nov/ahsanul.md`: build tag, COM ports, time from tile power-on to the first `BCN,`, any `missed`, whether GPIO4 was reachable. Dry-run CSVs are **not** committed.

## 9. When something goes wrong

| Symptom | Do this |
|---|---|
| No COM port when you plug in a tile | Try another cable (charge-only cables are common). Hold BOOT, tap RESET, release BOOT, then retry the flash. |
| ESP-4 sits in `boot:0x0 (DOWNLOAD...)` after a reset | Known issue: unplug and replug USB instead of pressing RESET. |
| Tile never prints `BCN,` | Check the image is for the right network, the router has AP isolation off, and the Pico prints `COORDINATOR up`. Power the Pico first, then the tile. |
| Tile prints `BCN,` but the Pico never logs `JOIN` for it | The tile now sends REGISTER 3 times (R1-1, merged). If there is still no JOIN after 5 s, power-cycle the tile and write down that it happened: that is a finding for Benjamin. |
| `foreign=` rising when no second Pico is meant to be there | Another Pico is on the network. Find it, or move to another SSID. Everything logged since then is suspect for sync tests. |
| `TS reseed` lines appearing repeatedly | A second clock source, or very late beacons. Note the count and the time, and check `foreign=`. |
| `ASSET manifest refused: ... does not fit RAM` | R1-3 refusing an asset that cannot fit. Note the size and the D5 minimum. Use a smaller asset (fewer frames) for the test. |
| Skew > 5 ms | Keep the evidence. Check that both tiles were JOINed and SYNC_READY before the capture began, then rerun **once** and write down what changed. |
| PC tool hears nothing (telemetry, uploader replies) | Laptop firewall (3.3 step 4), wrong network, or wrong tile IP (take it from the tile's `joined` line). |
| Analyser CSV has `UNPAIRED` lines | Copy them into the notes beside the tile's `DE missed=` value. Not a failure by itself. |
| A code bug blocks a P0 test | Tell Ahsanul at once (the section 1 gate). Do not edit code on your own branch. |

## 10. Logging rules and the results table

1. **One file per test,** at the path the card names. Raw logs are saved as they come off the device; never edited by hand. Your judgements go in your notes file (`docs/bench/5nov/<name>.md`), not in the log.
2. **Every log starts with the header line** from section 8 (tag, tile, image, network, Pico, who).
3. **Timestamps:** on for any card marked *Times needed*, and preferred everywhere.
4. **Pass or fail is decided from the lines each card names,** not from what it looked like. Quote the deciding line in your notes. For example: `D2 PASS: CL_STATS ... exc_max=0 (last line, 10:41:07)`.
5. **A failure is evidence too.** Commit the log, mark it FAIL, and give a one-line reason. Do not delete failed runs.
6. **Your notes file** has one row per test:

   | Test | Status (PASS / FAIL / PARTIAL / NOT RUN) | Deciding line or number | Evidence path | Tag | Time |
   |---|---|---|---|---|---|

7. **Commit and push:**
   - `git add <your evidence files> docs/bench/5nov/<name>.md`
   - commit message `Bench 5 Nov (<name>): <tests>`, with no AI trailers (the repo's `commit-msg` hook blocks them)
   - `git push origin bench/<name>-5nov` at 12:30 and 17:30, plus whenever a P0 test finishes.
   - Before your first commit, install the hook: `cp docs/tools/commit-msg .git/hooks/commit-msg`.
8. **At 17:30,** Ahsanul builds the master results table (every test in section 6, its status, and who) from the five notes files. Then he merges every `bench/*-5nov` branch into `b4/phase2` and runs `python pc/tools/evidence_index.py --inputs ../inputs`, which turns the evidence into the Green/Yellow/Red readiness table for Tribunal 2.
